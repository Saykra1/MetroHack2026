Round 3 (AI/ML layer)
- Built the service side against the ML contract (`experiments/ml`) and made it degrade cleanly: each file is optional, the load never raises, and `/health.ml` shows what is loaded and any load errors. Tested on synthetic fixtures first, then the real files arrived (intervals, anomalies, hybrid, hybrid_folds, REPORT.md). `prepare_data.py` copies them (`--ml-dir`) and removes stale copies. - `app/ml.py`: intervals are stored as P10/P50 and P90/P50 ratios, so the band follows v08, the hybrid and dispatcher corrections alike. Overflow probability uses a two-piece lognormal through P10/P50/P90 (P10 = 0 falls back to the other side's σ). Also: REPORT.md table parser with the Russian «питч» section as the summary, Russian anomaly labels, hybrid cubes, and `hybrid_weight_zero` detection (prediction == base).
- Aggregation of the band: hours of a day and routes are summed as fully correlated, days of a month as independent. With full correlation across days the December band would have been −32 %/+38 %; now it is −6 %/+7 %.
- API: `p10`/`p90` + `interval` in forecast/series/stop, P10/P90 export columns, `model=v08|hybrid` on every forecast endpoint (`Adj.model`, and the baselines use the same model), `/fleet` `plan_by` + `p_overflow` + `overflow`, new `/anomalies`, `/model`, `/assistant`.
- UI: «80 % интервал» band (day and month), KPI «Вероятность переполнения», overflow line and «Планировать по P90» in the fleet panel, anomaly dots with tooltips on the month history chart, «ИИ-детектор аномалий» panel (kind filter, click opens the month, informational «Исключить аномалии из обучения»), «Модель» card (REPORT tables, sources with links, factors, «Гибрид ML» toggle + filter-bar switch), «Помощник диспетчера» (rule-based, no LLM).

Round 4
- Bug «2nd chart under the map does not render». I reproduced it in headless Chrome and in the preview pane. Root cause: ECharts instances were resized only on window `resize`. A chart first drawn while the page or card was hidden or still being laid out (background tab, collapsed preview pane, mobile reflow) kept the 100 px fallback canvas and looked blank. The Leaflet map recovered through its own ResizeObserver, which is why only the charts broke. Fix: a ResizeObserver per chart container, plus a resize on `visibilitychange`. Also on phones (≤ 560 px) the wrapped filter bar was sticky and 387 px tall, covering half the screen; it is now static there. Regression tests: `tests/test_ui_e2e.py` (Playwright, skipped without Chrome) checks canvas = container after a hidden start at 1440 and 390 px, plus route × horizon × theme with no JS errors. The reported `dayLineTooltip` error is not in the current code: no such identifier exists, and there are no console errors in any combination. It most likely came from a stale cached `app.js`, so static assets are now versioned (`?v=`).
- Assistant normalisation (backend): `app/nlq.py` turns free text into a structured query {route, date_from, date_to, hour_from, hour_to, hour_ranges, granularity, corrections, intent, chips}. It handles: lower case, ё, typo repair via difflib against a vocabulary; сегодня/завтра/послезавтра, weekdays, «следующий понедельник»; «10 декабря», 10.12, ISO, «с 10 по 15 декабря», «17-го», «семнадцатого», «третьего числа», «в декабре»; «на 7-ке», «семерка», «семнадцатый трамвай», № 17; «в 8 утра», «в 7 вечера», 18:00, «с 7 до 10»; час пик = 07–10 and 16–20 (утренний/вечерний picks one), ночью/утром/днём/вечером; corrections (+10 %, дождь N мм, мороз, перекрытие ×0, частичное ×0,5, фестиваль ×1,2, пробки N баллов). A missing date falls back to the dashboard date and is flagged. `POST /api/v1/assistant/query` {text, ref_date, plan_by, query?}: an edited `query` replaces the parse, with the usual Russian 400/422 errors.
